# AMC live takeover evaluation

This is a small API-backed smoke test, not a production system or a scientific result.

It sends the same structured takeover question to one model under two clean conditions:

1. `summary` — the existing short handoff summary.
2. `capsule` — the existing Agent Memory Capsule (AMC) fixture.

The runner has no tools, web access, or shared conversation state. It grades only five explicit operational requirements: retain the city-tree goal, verify the license next, abstain from a recommendation, do not publish without approval, and label the license unverified.

## Run

From the repository root, after `OPENAI_API_KEY` is set:

```powershell
python -m pip install -e .\pilot\live_eval
python .\pilot\live_eval\run_local.py
```

The latest machine-readable result is written to `pilot/live_eval/results/latest.json`. It intentionally does not store credentials. A single synthetic case can only confirm that the harness works; it cannot demonstrate that AMC is superior. The next credible stage is at least ten independently constructed, task-relevant handoffs, with pre-registered graders and a blind review of failures.

## Event and compression experiment

`run_event_compression.py` compares a summary plus raw events, the full AMC plus raw events, and a compact current-state AMC generated by `pilot/compact_amc.py`. It measures minified JSON and gzip sizes and grades whether evidence invalidation and approval revocation change the agent's behavior.

```powershell
python .\pilot\live_eval\run_event_compression.py
```

## ID-only dependency experiment

`run_id_only_dependencies.py` sends terse identifier-only events to three handoff conditions. The summary is expected to request missing dependency context rather than invent it; the full and compact AMCs are expected to resolve the recorded links. Each condition runs three times.

Version 2 also requires exact affected claim IDs and treats equality between structured IDs as an explicit link. The compact projector now preserves a small `evidence_to_claims` map.

```powershell
python .\pilot\live_eval\run_id_only_dependencies.py
```

## Gate-ordering experiment

`run_gate_ordering.py` compares the summary, full AMC, compact current view, and a compact gated view. It observes whether the agent separates actions allowed now from future actions and preserves the required order through publication.

```powershell
python .\pilot\live_eval\run_gate_ordering.py
```

## Failure Space AMC experiment

`run_failure_space.py` compares exact repetition, delta-only updates, complementary Failure Space, and a deliberately slipped `required` → `optional` license instruction across continued multi-turn conversations. Every proposed action is checked by the deterministic dispatcher.

The runner separately reports all invalid transition proposals and the high-risk subset involving premature approval or publication. `regrade_failure_space.py` applies those corrected metrics to a previously saved raw result without making API calls.

```powershell
python .\pilot\live_eval\run_failure_space.py
python .\pilot\live_eval\regrade_failure_space.py
```

## Round B finalist smoke test

`round_b_smoke.py` compares the four deterministic Round A frontier variants,
a full-history control, and an intentionally incomplete control across five
held-out dispatcher phases. The schedule is seeded, randomized, and checkpointed
after each call. It makes 60 calls by default: five tasks, six conditions, and
two repetitions.

```powershell
python -m pilot.live_eval.round_b_smoke
python -m pilot.live_eval.regrade_round_b
```

The regrader makes no API calls. It preserves raw decisions and corrects an
identifier-impact oracle that was exact for evidence invalidation but ambiguous
for other event types. Raw and regraded results are stored separately under
`pilot/live_eval/results/`.
